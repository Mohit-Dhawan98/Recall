  2. `test_handle_message_with_multiple_urls` [NORMAL] - Message with two URLs. Mock `save_article` to return success for both. Verify reply_text called, and `save_article` was called twice.

  3. `test_handle_message_no_url` [EDGE] - Message with no URLs. Verify reply_text called with "couldn't find any links" message.

  4. `test_handle_message_api_error` [EDGE] - Message with URL where `save_article` raises `httpx.HTTPStatusError`. Verify reply_text called with "Failed" in response.

  5. `test_handle_message_duplicate_url` [NORMAL] - Mock `save_article` to return `{"status": "duplicate"}`. Verify reply_text contains "Already saved".

  **Important:** Mock `bot.main.save_article` as an AsyncMock rather than trying to mock httpx directly. This is cleaner since `save_article` is the boundary between handler logic and API communication.

  ```python
  from unittest.mock import patch, AsyncMock
  import httpx

  @pytest.mark.asyncio
  async def test_handle_message_with_single_url(mock_update, mock_context):
      """[BASE] Single URL message saves article and confirms."""
      mock_update.message.text = "Check this out: https://example.com/article"

      with patch('bot.main.save_article', new_callable=AsyncMock) as mock_save:
          mock_save.return_value = {"id": "abc-123", "status": "processing", "message": "Saved"}

          from bot.main import handle_message
          await handle_message(mock_update, mock_context)

          mock_save.assert_called_once()
          mock_update.message.reply_text.assert_called_once()
          reply = mock_update.message.reply_text.call_args[0][0]
          assert "Saved" in reply
  ```
