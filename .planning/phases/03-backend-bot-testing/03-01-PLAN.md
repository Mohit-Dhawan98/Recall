  **Test class: TestCaptureIntegration** (requires Docker/testcontainers)

  Tests to implement:

  1. `test_full_capture_pipeline` [BASE] - Submit URL via POST /api/articles with mocked `fetch_url` (returns sample HTML) and mocked `analyze_content` (returns AnalysisResult with summary, tags, entities). Wait briefly for background task. Verify:
     - Response status 200 with status "processing"
     - Article in database has processing_status "completed"
     - Article has summary from mocked LLM
     - Tags and entities were created in database
     - GET /api/articles/{id} returns the processed article with all fields

  2. `test_capture_retrieves_via_api` [NORMAL] - After capturing, use GET /api/articles to list articles. Verify the captured article appears in the list with correct summary and tags.

  3. `test_duplicate_url_returns_duplicate_status` [NORMAL] - Submit the same URL twice. First returns "processing", second returns "duplicate" with the existing article ID.

  4. `test_background_task_failure_marks_article_failed` [EDGE] - Submit URL where `analyze_content` raises an Exception. Verify:
     - Article exists in database
     - Article has processing_status "failed"
     - The exception is re-raised (the background task propagates it)

  5. `test_extraction_failure_returns_error` [EDGE] - Submit URL where `fetch_url` raises an Exception. Verify the API returns an error response (status >= 400).

  **Mocking strategy:**
  - Mock `app.services.extractor.fetch_url` to return sample HTML (avoid real HTTP)
  - Mock `app.services.llm.analyze_content` to return an AnalysisResult (avoid real LLM calls)
  - Mock `app.services.llm.generate_embedding` to return None (avoid real embedding calls)
  - Mock `app.services.graph.build_relations_for_article` to return [] (avoid graph complexity)
  - Use real database via testcontainers (already in conftest.py)

  **Important implementation details:**
  - Import `AnalysisResult` from `app.services.llm` for mocking analyze_content return value
  - The `client` fixture in conftest.py already creates a default user with api_key "default-api-key"
  - Use `headers={"X-API-Key": "default-api-key"}` for all authenticated requests
  - After POST, add `await asyncio.sleep(0.2)` to let background task complete
  - For the background task failure test, you may need to call `process_article_background` directly and catch the exception, since background tasks swallow exceptions in FastAPI
  - Use `from unittest.mock import patch, AsyncMock` for mocking
  - The `process_article_background` function uses `AsyncSessionLocal` directly, so the conftest fixture must patch this

  **Auth note:** The `client` fixture depends on `default_user` which creates a user with api_key "default-api-key". Use this key in X-API-Key header.
